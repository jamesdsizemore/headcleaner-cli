# 0002 — OKF v0.2 as the canonical knowledge format

**Status:** Accepted
**Date:** 2026-08-20
**Context:** Phase 2 requires a portable canonical output for converted documents. The output must be machine-readable, human-readable, and durable across runs. Options considered: OKF v0.2, custom JSON Schema, plain Markdown with custom frontmatter.

**Decision:** Use OKF v0.2 as the canonical format, with headcleaner extending the trust family. OKF v0.2 is a public specification with a defined trust family (`type`, `status`, `generated`, `verified`, `stale_after`, `sources`); downstream tools that understand OKF can ingest headcleaner output without knowing anything about headcleaner itself.

**Consequences:**

- The canonical output is portable between knowledge-management tools.
- The trust family is mandatory; headcleaner always emits the full set on every concept.
- Adding headcleaner-specific fields requires care: they go under documented extension points, not by overloading the OKF vocabulary.
- The format does not provide a chunking or search specification; those are headcleaner-specific derivatives.
