feat(v0.13.0): cross-bundle search + @slug registry (MCP)

`headcleaner mcp` gains cross-bundle search and a persistent @slug
registry, mirroring `serradura/okf-gem`'s registry concept.

**Cross-bundle search:** okf_search now accepts all_bundles=True. When
set, every loaded bundle is searched and each hit includes a `bundle`
field.

**@slug registry:** a TOML file at ~/.config/headcleaner/registry.toml
maps friendly slugs to bundle paths. Override with $HEADCLEANER_REGISTRY.

Four new MCP tools:
- okf_registry_list         # List @slug aliases
- okf_registry_add          # Register a bundle under a slug
- okf_registry_remove       # Unregister a slug
- okf_registry_resolve      # Resolve @slug/concept to (bundle_path, concept)

@slug/concept syntax works in okf_get_concept, okf_context, okf_related,
and okf_impact. The slug is auto-loaded if the bundle isn't yet in
memory.

**Implementation:**

- src/headcleaner/registry.py (new, 108 LOC) — TOML load/save/add/remove
  + validate slug names
- src/headcleaner/mcp.py — @slug resolution in _resolve_concept_id,
  cross-bundle search in okf_search, 4 new @mcp.tool() wrappers
- pyproject.toml — tomli-w>=1.0 added as runtime dep (stdlib tomllib
  handles reading)

**Tests:** 16 new tests (330 passed total, +16 vs v0.12.0).

**Docs:** docs/REGISTRY.md (new), docs/CHANGELOG.md updated.

Follows the @slug concept from serradura/okf-gem (Apache-2.0, 122 stars).
TOML chosen over JSON because "my-org/kb" style slugs are valid TOML
without quoting.
